# 5주차 — 검증 가능한 다국어 보상 함수와 RAG 준비도

## 목표

코드로 확정 가능한 출력 조건을 보상 하네스로 기록하고, 정상 기준선과 주입 오류에서 동작을 확인한다. 평가는 4주차의 held-out 40건을 그대로 사용하며 학습·프롬프트 예시·검색 인덱스로 사용하지 않는다. RAG는 검색이 필요한 오류와 사용 권리가 확인된 표현 자료가 있을 때만 비교한다.

## 보상 설계

`npm run evaluate:reward`가 `data/evaluation-set-v2.json`의 각 기준선 출력에 다음 항목을 적용한다.

| 항목 | 보상 통과 조건 | 판정 범위 |
|---|---|---|
| `schema_valid` | 언어별 필수 필드, 타입·레벨 값이 유효하고 예상 밖 필드가 없다 | 출력 구조만 확인 |
| `source_grounded` | 추출 표현이 정규화한 원문에 포함된다 | NFKC·공백 정리, 곡선/직선 아포스트로피 정규화; 중국어·일본어 공백 무시 |
| `phrase_length_valid` | `config/languages.json`의 언어별 길이 제한에 든다 | 영어·프랑스어는 단어, 중국어·일본어는 코드 포인트 수 |
| `target_script_compatible` | 중국어/한자·가나 또는 라틴 문자 조건을 만족한다 | 스크립트 적합성만 확인하며 언어 정체성은 증명하지 않음 |
| `pronunciation_format_valid` | 중국어 발음 필드에 라틴 문자가 있고 일본어 읽기 필드는 가나만 쓴다 | 발음·성조·읽기의 실제 정확성은 확인하지 않음 |
| `korean_fields_present` | 뜻과 설명 필드에 한글이 포함된다 | 번역의 의미·자연스러움은 확인하지 않음 |

합성 보상은 모든 항목을 통과할 때 `1`, 하나라도 실패하면 `0`이다. 이는 다음 학습 실험에서 검토할 적격성 신호일 뿐, 표현의 자연스러움이나 의미 정확성을 뜻하지 않는다.

\* 이번 보상 하네스의 정규화 기준. 4주차 기준선 스크립트는 곡선/직선 아포스트로피를 정규화하지 않아 프랑스어 `fr-06`, `fr-08`을 원문 밖으로 잘못 셌다. 이 실행에서는 두 표현을 원문에 포함된 것으로 판정했다. 기존 평가 결과 파일은 수정하지 않았다.

생성 요청 2건이 실패했다: 중국어 `zh-04`, 프랑스어 `fr-04`. 둘 다 타임아웃 오류를 반환했다. `zh-04`의 기록된 경과 시간은 940,060ms로 설정한 240,000ms 요청 제한을 크게 넘는다. 제한 시간 동작과 원인을 후속 조사해야 한다.

보상 탈락 사례는 `zh-03`(원문 밖 표현), `zh-04`(요청 실패), `zh-10`(원문 밖 템플릿 `太...了`), `en-05`(설정된 최대 단어 수 초과), `fr-04`(요청 실패), `ja-06`(원문 밖 표현), `ja-08`(로마자 읽기)다. `ja-06`의 읽기는 가나 형식이지만 정확한 읽기인지는 이 하네스가 판정하지 않는다.

## 오류 주입 및 반복 판정

40건 각각에 원문 밖 표현, 잘못된 스크립트, 최소 길이 미달, 필수 필드가 빠진 스키마 오류를 하나씩 만들어 총 160건을 점검했다. 각 주입 사례에서 의도한 검사 항목이 실패해 **160/160을 탐지**했다. 같은 기준선 출력을 항목별로 10회 재채점해 **40/40 사례에서 결과가 일치**했다.

이 결과는 코드가 주입한 패턴을 일관되게 거르는지 확인한 것이다. 자연 발생 오류 전체의 탐지율이나 모델 생성의 반복 안정성을 측정한 것은 아니다. 점수 반복은 동일 출력의 결정성만 확인했다.

## RAG 결정

이번 실행에서는 RAG를 만들거나 실행하지 않았다. 40건 평가셋은 held-out이므로 색인에 넣을 수 없고, 저장소에서 별도로 사용 권리가 기록된 표현 코퍼스를 확인하지 못했다. 아티클 기반 예시도 재사용 권리가 기록되어 있지 않아 지식 베이스로 복사하지 않았다. 허가된 짧은 표현 자료와 실제 검색 필요 오류가 확보되면 별도 인덱스를 만들고, 검색 근거 포함 여부 및 동일 평가 사례의 오류 변화를 비교한다.

별도 RL 학습 예시도 만들지 않았다. 검수된 user-provided/licensed 예시가 현재 확인되지 않아, held-out 데이터를 복제하거나 학습 자료로 재사용하지 않았다. 로컬 LLM 평가는 4주차에서 잘못된 고득점과 일본어 읽기 형식 오판이 확인되어 이번 보상 판정에는 넣지 않았다.

## 해석과 다음 단계

- 보상 신호는 구조·원문 근거·길이·스크립트·필드 형식 확인에는 쓸 수 있지만 의미 정확도, 초급 학습 가치, 자연스러움 판정에는 충분하지 않다.
- 영어와 프랑스어는 모두 라틴 문자라 현재 스크립트 검사로 서로 구분되지 않는다. 중국어/일본어의 한자 사용도 스크립트 적합성만으로 의미 언어를 증명하지 못한다.
- 병음 검사는 라틴 문자 필드 존재 수준이며 성조·음절 정확성을 검증하지 않는다. 일본어는 가나 형식만 확인한다.
- 보상 탈락 사례를 독립적으로 사람이 검토하지 않았다. 사람의 오류 검토와 신뢰할 수 있는 언어 정체성 검증 전에는 이 신호를 실제 RL 학습에 넣지 않는다. 현재 결과만으로 품질 개선을 주장하지 않는다.
- 다음 단계는 타임아웃 원인과 중국어·일본어 기준선 오류를 검토하고, 검수된 별도 학습 예시 및 합법적인 RAG 자료가 확보됐는지 확인하는 것이다.

## 재현

```powershell
npm run evaluate:model
npm run evaluate:reward
```

`evaluate:reward`는 현재 v2 평가셋 해시와 사례 ID가 모두 맞는 기준선 결과만 받아들인다. 실행 결과는 고유한 타임스탬프 파일로 `results/`에 추가되며 기존 결과를 덮어쓰지 않는다.
